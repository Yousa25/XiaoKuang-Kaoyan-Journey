# 2.4.1 线性表的顺序存储表示（C语言定义）

## 一、 基础概念回顾
*   **逻辑结构到物理结构的映射**：逻辑上相邻的元素（$a_1, a_2, \dots$），在物理内存中也是相邻的。
*   **⚠️ 核心注意点（图中高亮）**：**逻辑位序和物理位序相差1**。
    *   逻辑上的第 $i$ 个元素，其在数组中的物理下标（索引）为 `i - 1`。

## 二、 顺序表的 C 语言结构体定义

在 C 语言中，顺序表通常包含三个关键部分：**数据元素、存储空间、表长度**。

### 1. 静态分配（基础版）
使用固定大小的数组来存储数据，编译时内存大小就已确定。
*   **代码示例**：
    ```c
    #define MAXSIZE 100 // 定义顺序表的最大容量
    typedef struct {
        ElemType elem[MAXSIZE]; // 静态数组，存放数据元素
        int length;             // 记录当前顺序表中实际元素的个数
    } SqList;
    ```
*   **特点**：`elem` 数组本身就在结构体内部，大小固定为 `MAXSIZE`，无法动态改变。

### 2. 动态分配（进阶版）
使用指针和动态内存分配函数，可以在程序运行时按需申请内存空间。
*   **代码示例**：
    ```c
    typedef struct {
        ElemType *elem; // 指向动态分配的数组首地址的指针
        int length;     // 记录当前顺序表中实际元素的个数
    } SqList;

    // 初始化/分配内存（使用malloc函数）
    // 假设 ElemType 为 int，这里申请了 MAXSIZE 个 int 空间
    L.elem = (ElemType*)malloc(sizeof(ElemType) * MAXSIZE);
    ```
*   **特点**：`elem` 是一个指针，指向堆区（Heap）的内存，空间大小可以动态调整，灵活性更高。

---

## 💡 易错点与避坑指南

1.  **静态数组与动态指针的区别**
    *   **易错点**：在写代码时，混淆静态数组定义 `ElemType elem[MAXSIZE]` 和动态指针定义 `ElemType *elem`。
    *   **避坑**：如果结构体内部是指针，**必须**在后续代码中使用 `malloc()` (或 `new` 在C++中) 为其在堆上分配内存，否则指针会成为野指针，导致程序崩溃。

2.  **`length` 的初始值**
    *   **易错点**：创建顺序表后，忘记将 `length` 初始化为 0，或者错误地初始化为 `MAXSIZE`。
    *   **避坑**：一个刚初始化、尚未存入数据的空表，其 `length` 绝对应该是 `0`。`MAXSIZE` 只是它的**最大容量**，而非当前长度。

3.  **逻辑位序与数组下标的越界问题**
    *   **易错点**：在遍历或操作顺序表时，循环条件写成 `i <= length` 导致数组越界（下标访问到 `length` 处，而最后一个有效元素的下标是 `length - 1`）。
    *   **避坑**：牢记循环遍历的条件应该是 `i < length`。

# 顺序表变量定义与内存结构解析

## 一、 核心代码与类比
*   **定义顺序表类型**：
    ```c
    #define MAXSIZE 100
    typedef struct {
        ElemType *elem; // 动态数组的基地址（指向数组首元素的指针）
        int length;     // 顺序表当前的实际长度（元素个数）
    } SqList; // 结构体类型别名
    ```
*   **定义顺序表变量**：
    ```c
    SqList L; // 定义了一个名为 L 的顺序表变量
    ```
*   **通俗类比**：
    *   `typedef struct {...} SqList;` 类似于 `int a;` 中的 `int`（定义了一种数据类型）。
    *   `SqList L;` 类似于 `int a;` 中的 `a`（定义了一个该类型的变量）。因此，**`L` 就是一个具体的顺序表**。

## 二、 顺序表变量 L 的内存结构
当我们在代码中定义 `SqList L;` 时，变量 `L` 在内存中包含了两个核心成员：
1.  **`L.elem`（数据区指针）**：它本身是一个指针变量，存储了动态数组的**首地址**。通过这个指针，我们可以访问到 `L.elem[0]`, `L.elem[1]`, `...`, `L.elem[99]` 等物理内存块。
2.  **`L.length`（元数据区）**：一个普通的整型变量，用于记录当前顺序表中**实际存放了多少个元素**。

> *图中示例解析*：图中线性表 `L` 里存放了 7 个元素 (`a` 到 `g`)，因此数组下标从 0 到 6，而 `L.length` 的值就是 7。

---

## 💡 易错点与避坑指南

1.  **混淆“数组最大容量”与“表实际长度”**
    *   **易错点**：把 `MAXSIZE`（数组开辟的最大空间，图中为100）当成 `L.length`（当前实际长度，图中为7）。
    *   **避坑**：明确两者区别。`MAXSIZE` 是“仓库的最大容量”，`L.length` 是“仓库当前实际装了多少货”。

2.  **忽视 `L.elem` 的指针属性**
    *   **易错点**：误以为 `L.elem` 直接存了所有数据。实际上 `L.elem` 只是一个指针（占4或8字节），它指向堆区的一段连续内存空间。
    *   **避坑**：必须牢记 `elem` 是用 `*` 修饰的指针。在初始化顺序表时，必须使用 `malloc` 或类似函数为其动态分配 `sizeof(ElemType) * MAXSIZE` 的内存空间，否则直接存取会导致内存错误。

3.  **混淆“顺序表长度”与“数组下标”**
    *   **易错点**：将 `L.length` 当作数组下标来直接读取数据。例如图中有 7 个元素，若写 `L.elem[L.length]` (即 `L.elem[7]`)，就会越界访问到无效数据。
    *   **避坑**：牢记 **下标 = length - 1**。`L.length` 仅用于判断表是否为空、是否满，或者在表尾插入数据时使用。

# 2.4.2 顺序表基本操作的实现：初始化

## 一、 函数定义与签名
*   **函数原型**：`Status InitList_Sq(SqList &L)`
*   **参数解析（图中重点强调）**：参数 `SqList &L` 使用了**引用（&）**传递。
    *   **为什么要用引用？** 因为初始化的本质是在函数内部为 `L` 分配内存空间并设置其属性。使用引用可以确保函数内部对 `L` 的修改，能够**直接反映到调用函数外部的实际变量上**。如果传值（不写 `&`），函数内修改的只是副本，外部的 `L` 依然未初始化。

## 二、 核心代码逻辑拆解
1.  **分配空间**：
    *   `L.elem = new ElemType[MAXSIZE];`
    *   使用 `new` 关键字（C++语法，类似 C 语言的 `malloc`）动态分配一个大小为 `MAXSIZE` 的数组空间，并将首地址赋值给 `L.elem`。
2.  **异常处理**：
    *   `if(!L.elem) exit(OVERFLOW);`
    *   如果分配内存失败，指针 `L.elem` 将为空（`NULL` 或 `nullptr`），此时程序应抛出异常或安全退出，防止空指针访问。
3.  **初始状态设定**：
    *   `L.length = 0;`
    *   刚创建出来的顺序表是空的，因此其**逻辑长度**必须初始化为 0。
4.  **返回状态**：
    *   `return OK;` 表示初始化成功。

---

## 💡 易错点与避坑指南

1.  **混淆“空表”与“空指针”**
    *   **易错点**：认为 `L.length = 0` 就意味着 `L.elem` 也是空的（NULL）。
    *   **避坑**：空表（`length=0`）是指**已经成功分配了内存空间，只是还没有存入任何数据**；而 `L.elem` 为空则是**根本没有分配到内存**，是系统异常状态。
2.  **忘记检查内存分配结果**
    *   **易错点**：写完 `new` 或 `malloc` 后直接开始存取数据。
    *   **避坑**：动态内存分配可能失败（如系统内存耗尽），必须加上 `if(!L.elem)` 的判断，否则后续对 `L.elem` 的操作会导致程序崩溃。
3.  **`new` 语法与 `malloc` 的混用**
    *   **注意**：图中使用的是 C++ 的 `new` 关键字，它比 C 语言的 `malloc` 更现代且不易出错。如果你使用的是纯 C 环境编译，必须将 `new ElemType[MAXSIZE]` 替换为 `(ElemType*)malloc(sizeof(ElemType) * MAXSIZE)`。

# 2.4.2 补充：销毁与清空操作

在顺序表的操作中，“销毁”和“清空”有着本质的区别，分别对应着内存资源的释放和逻辑状态的恢复。

## 一、 销毁线性表 L
*   **核心代码**：
    ```cpp
    void DestroyList(SqList &L) {
        if (L.elem) {
            delete L.elem; // 释放存储空间
            // (注：实际编程中通常还会将 L.elem = NULL 和 L.length = 0)
        }
    }
    ```
*   **作用解析**：彻底销毁该顺序表。如果底层的数组指针 `L.elem` 存在（即已经分配过内存），则使用 `delete` 关键字将其占用的内存空间完全释放掉。销毁后，该顺序表变量将无法再使用。

## 二、 清空线性表 L
*   **核心代码**：
    ```cpp
    void ClearList(SqList &L) {
        L.length = 0; // 将线性表的长度置为0
    }
    ```
*   **作用解析**：逻辑上清空表内的所有元素。它仅仅是将记录表长的 `length` 变量置为 0。
*   **关键点**：顺序表底层的数组空间**依然存在**，并没有被释放。清空后，你可以继续往这个表里添加新元素。

---

## 💡 易错点与避坑指南（核心对比）

1.  **“销毁”与“清空”的本质区别**
    *   **易错点**：认为把表里的数据清空了，就等同于销毁了表，或者认为清空就是把内存也释放掉。
    *   **避坑**：
        *   **销毁 (`DestroyList`)** = **物理释放**内存空间。表彻底不存在了，想再用必须重新初始化 (`InitList`)。
        *   **清空 (`ClearList`)** = **逻辑置空**。表的空间还保留着，只是里面没有元素了（`length=0`），可以直接进行插入等后续操作。

2.  **为什么都要用引用传递 (`SqList &L`)？**
    *   **易错点**：函数定义时漏写 `&`。
    *   **避坑**：无论是销毁还是清空，都是要**修改**外部的顺序表变量 `L`（改变它的内存指针或者长度属性）。如果不用引用传递，函数内部修改的只是形参副本，外部的原表没有任何变化。

3.  **销毁时的防御性编程 (`if (L.elem)`)**
    *   **易错点**：直接写 `delete L.elem;`。
    *   **避坑**：如果 `L.elem` 本来就是空的（比如一个未初始化的顺序表，或者已经被销毁过一次的顺序表），直接 `delete` 可能会导致程序崩溃。因此，先判断 `if (L.elem)` 是否存在，是一个良好的编程习惯。

# 2.4.2 补充：求长度与判空操作

## 一、 求线性表L的长度
*   **功能**：返回当前顺序表中实际存储的元素个数。
*   **核心代码**：
    ```c
    int GetLength(SqList L) {
        return (L.length);
    }
    ```
*   **代码解析**：直接返回结构体中的 `length` 成员变量即可。

## 二、 判断线性表L是否为空
*   **功能**：判断当前顺序表中是否没有任何元素。
*   **核心代码**：
    ```c
    int IsEmpty(SqList L) {
        if (L.length == 0) return 1; // 条件成立，返回1（真），表示表是空的
        else return 0;               // 否则返回0（假），表示表不为空
    }
    ```
*   **代码解析**：判断表是否为空，本质上就是判断其 `length` 是否为 0。

---

## 💡 易错点与避坑指南

1.  **参数传递：传值 vs 传引用**
    *   **注意**：在这两个函数中，参数使用的是 **传值** `SqList L`，而不是传引用 `SqList &L`。
    *   **为什么可以传值？** 因为这两个操作仅仅是**读取**线性表的数据（只读操作），不需要在函数内部修改外部传入的顺序表。传值不仅符合逻辑，还能防止意外修改原表，保证了数据的安全性。

2.  **判空逻辑的核心**
    *   **易错点**：在判断表空时，容易去检查数据指针 `L.elem` 是否为空（即 `if (!L.elem)`）。
    *   **避坑**：**“表为空”和“表未初始化（指针为空）”是两个概念。** 判空操作的前提是表已经被初始化了，此时它仅仅表示“没有数据元素”，所以**必须通过判断 `L.length == 0`** 来实现。

3.  **C语言基础细节**
    *   **易错点**：在 `IsEmpty` 函数的 `if` 判断条件中，把比较运算符 `==` 错写成赋值运算符 `=`。
    *   **避坑**：图中代码 `L.length == 0` 明确使用了双等号进行比较。在实际编程和考试中，这是极其基础的语法点，需格外小心。

# 【算法2.2】顺序表的取值

## 一、 函数定义与功能
*   **功能**：根据给定的**逻辑位置 $i$**，获取顺序表中相应位置数据元素的内容。
*   **函数原型**：`int GetElem(SqList L, int i, ElemType &e)`
*   **参数解析**：
    *   `SqList L`：传入的顺序表（只读，不需要修改，故传值）。
    *   `int i`：要获取元素的**逻辑位置**（如第1个、第3个）。
    *   `ElemType &e`：**引用传递**（图中红圈标注）。用于将取出的值“带出”函数返回给调用者。因为是只读，所以使用 `const ElemType &e` 会更严谨，但此处核心是为了带回数据。

## 二、 核心代码逻辑拆解
1.  **边界合法性判断（图中红线标注）**：
    *   `if (i < 1 || i > L.length) return ERROR;`
    *   **作用**：位置 $i$ 必须是合法的自然数（从1开始），且不能超过当前表长。越界则直接报错。
2.  **核心取值操作（图中重点红圈）**：
    *   `e = L.elem[i-1];`
    *   **作用**：将顺序表底层数组中下标为 `i-1` 的元素赋值给引用变量 `e`。

---

## 💡 易错点与避坑指南

1.  **逻辑位置 vs 数组下标（最核心的易错点）**
    *   **易错点**：写代码时直接用 `L.elem[i]` 去取值。
    *   **避坑**：顺序表的元素位置（第1个、第2个...）是从 **1** 开始的；而C语言数组的下标是从 **0** 开始的。两者之间相差 1。
    *   **公式记忆**：图中老师特意写了 `a1` 对应 `0`，`ai` 对应 `i-1`。**第 $i$ 个元素 = `L.elem[i-1]`**。

2.  **参数 $i$ 的合法范围**
    *   **易错点**：判断边界时使用 `if (i < 0 || i >= L.length)`，这是数组下标的判断方式。
    *   **避坑**：因为参数 $i$ 代表的是“第几个元素”，所以它的合法范围是 **$[1, L.length]$**。必须严格对应图中的 `i < 1 || i > L.length`。

3.  **返回值类型**
    *   **注意**：函数的返回值是 `int` 类型，返回的是**操作状态**（`OK` 或 `ERROR`），而不是取出的数据元素本身。真正取出的数据是通过参数 `e` 的引用传递带回的。
